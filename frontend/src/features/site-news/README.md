# 공지·업데이트 소식

사이트 머리말의 [공지](`/notices`)와 [업데이트 소식](`/releases`)에 보이는 글이에요. 글 하나가 파일 하나이고, 빌드할 때 화면에 함께 들어가요(서버·DB 없음). 새 글은 파일을 더하고 main에 머지하면 다음 배포부터 보여요.

## 공지 (`notices/날짜-이름.md`)

```
<!-- title: 공지 제목 -->
<!-- date: 2026-10-12 -->
본문 (문단, `### 소제목`, `- 목록`, 그림 줄만 써요)
```

## 업데이트 소식 (`releases/vX.Y.Z.md`)

- 1.0.0: 첫 배포·출시 (2026-10-10, PR #1~#37)
- 그 뒤 버전: 앞 버전 배포 이후 수정사항(1.5.1이면 "1.5.0 배포 이후 수정사항"). 평일은 오후 6시 기준, 주말은 주말 동안 바뀐 것을 묶어요. 바뀐 게 없으면 건너뛰어요.

```
<!-- target: 이 버전 마지막 머지 커밋의 SHA 40자 -->
<!-- title: BaseLOG (앞 버전) 배포 이후 수정사항 -->
<!-- date: 2026-10-12 -->
본문. 항목 끝 괄호의 PR 번호 (#39)는 사이트에서는 숨겨요.
```

### 그림 (전후 비교)

화면이 바뀐 항목 바로 아래에 그림만 있는 줄을 둬요. 한 줄에 두 장이면 나란히(폰에서는 위아래로) 보여요. 그림 파일은 `releases/images/vX.Y.Z/`에 두고, 글 폴더 기준 경로로 적어요.

```
- 닉네임을 바꿀 때 조건과 사용 가능 여부가 바로 보여요 (#120)
![전](images/v1.3.0/nickname-before.png) ![후](images/v1.3.0/nickname-after.png)
```

- 전 = 지금 사이트(main), 후 = dev. 같은 화면·같은 창 크기(1280px 너비)로 찍고, PNG는 한 장 300KB 안쪽으로 줄여요.
- 화면이 바뀌지 않은 항목(버그 수정, 서버 쪽 변경)은 그림 없이 둬요.
- 없는 그림을 가리키면 `siteNews.test.ts`가 실패해요.

main에 머지되면 `.github/workflows/release.yml`이 GitHub Releases에도 같은 내용을 등록해요(아직 없는 버전만). 루트 `CHANGELOG.md` 맨 위에 한 줄 요약도 더해요.
